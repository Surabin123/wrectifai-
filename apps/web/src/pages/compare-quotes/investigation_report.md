# Root Cause Investigation: WrectifAI Estimate Showing `DEBUG: null/undefined`

## 1. Source of the WrectifAI Estimate
The estimate is generated by `QuoteEstimationService.generateLocalEstimate(id)` and is stored in the `quote_requests` table under the `ai_estimate` JSONB column.

## 2. API Endpoint Trace
The frontend calls `fetchAiEstimate(reqId)`, which hits the Express backend at:
`POST /api/v1/quotes/requests/:id/estimate`

The backend logic (`quotes.routes.ts`):
1. **Fetch**: `SELECT vehicle_id, issue_summary, ai_estimate FROM quote_requests WHERE id = $1`
2. **Check Current**: If `ai_estimate` exists, return it immediately via `success(res, ai_estimate)`.
3. **Check Related**: If missing, check if any identical request from the same user has an estimate, sync it, and return it.
4. **Generate**: If none exist, call `QuoteEstimationService.generateLocalEstimate(id)`, update the database, and return it.

## 3. Frontend Trace (`compare-quotes-page.tsx`)
```typescript
let reqId = null;
if (ids) {
  const selectedQuotes = data.filter((q) => ids.includes(q.id));
  if (selectedQuotes.length > 0) reqId = selectedQuotes[0].quoteRequestId;
}
if (!reqId) reqId = data[0]?.quoteRequestId || reqs[0]?.id;

if (reqId) {
  fetchAiEstimate(reqId).then(est => {
    ... parse logic ...
    setAiEstimate(parsedEst);
  }).catch(err => {
    setFetchError(err?.message);

```

## 4. Root Cause Analysis
The UI currently displays `DEBUG: null/undefined`. 
Based on the code, `getAiRange` returns this exact string ONLY when `!aiEstimate` is true AND `fetchError` is falsy.

This proves that **`fetchAiEstimate` DID NOT throw a network or server error** (otherwise `fetchError` would be populated and the UI would show `DEBUG ERROR: [message]`).

Therefore, one of two things is happening:

### Possibility A: `reqId` is falsy (The API is never called)
If `reqId` is `undefined` or `null`, the `if (reqId)` block is skipped. `fetchAiEstimate` is never called, `aiEstimate` remains its initial state (`null`), and the UI immediately renders `DEBUG: null/undefined`.
**Why this could happen:** If the quotes fetched by the frontend (`data`) somehow have a missing or undefined `quoteRequestId` property. (Though the backend uses an INNER JOIN on `quote_requests`, so it technically shouldn't be null in the DB).

### Possibility B: The Backend returns a successful 200 OK with an empty body
If `fetchAiEstimate` is called, but the backend returns a 200 OK with `{ "data": null }` or `{ "data": "" }`, `est` resolves to `null`. The parsing loop skips, and `setAiEstimate(null)` is called.
**Why this could happen:** If `ai_estimate` in the database is literally the string `""` or the JSON literal `null`, it bypasses the falsy checks and the API returns it as `null`.

## 5. Conclusion & First Point of Failure
The first point where the value becomes null/undefined is either:
1. **Before the API call**, because `reqId` (derived from `selectedQuotes[0].quoteRequestId`) is undefined.
2. **Inside the API response payload**, where `json.data` is returned as `null` or `""` despite a 200 OK status.
